# مسار العمليات ومسارات الاعتماد — Operations workflow

كل حالة في النظام تظهر بنص + نقطة + لون (مش لون بس). أي إجراء حساس بيتسجل في **سجل الإجراءات** بالقيم القديمة والجديدة والسبب. لا يعتمد أي مستخدم طلبًا أنشأه بنفسه (فصل المهام)، وحدود المبالغ تيجي من **مصفوفة الاعتماد** في الإدارة، مش مكتوبة في الكود.

## 1) دورة المشروع (المشاريع الداخلية)

```
برنامج ──► مشروع (مسودة) ──► إرسال للمالية ──► مراجعة مالية ──► معتمد ماليًا ──► متاح للتحصيل
                ▲                                   │
                └──────── معاد للمركز ◄─────────────┤──► مرفوض
                                                    └──► موقوف ◄─► استئناف
```

للمشروع ثلاث حالات مستقلة:

| المحور | القيم |
|---|---|
| الاعتماد المالي | مسودة · بانتظار المالية · قيد المراجعة · معاد للمركز · معتمد ماليًا · مرفوض · موقوف |
| التحصيل | غير متاح · متاح · موقوف · بلغ السقف · مغلق |
| التنفيذ | لم يبدأ · جارٍ · متوقف · مكتمل · ملغى · مقفل |

- **مسؤول المركز** يُنشئ المشروع داخل برنامج (المشروع المنفرد يُنشأ له برنامج بنفس الاسم تلقائيًا) ويرسله للمالية.
- **المراجع المالي** يراجع الاكتمال، يربط المشروع **ببند مالي** وبـ**ترخيص/تراخيص**، ثم يعتمد أو يعيد أو يرفض. الاعتماد يحفظ الربط أولًا ثم يرسل رسالة إتاحة لنظام التحصيل.
- أي **تغيير جوهري** بعد الاعتماد يرجع للمالية قبل ما يُطبَّق.
- **التراخيص**: السقف مشترك على مستوى الترخيص. المعاملات المعلقة تحجز جزءًا منه. عند التحصيل يُستهلك الترخيص الأقرب انتهاءً أولًا، والفحص يتم داخل قفل SQL (`sp_getapplock`) عشان مفيش تحصيلين في نفس اللحظة يعدّوا السقف.

## 2) الميزانية والصرف

```
مسودة ─► مراجعة المختص ─► التحقق المالي من التمويل ─► الاعتماد والحجز ─► تنفيذ جزئي/كلي ─► (تحرير المتبقي)
            │                     │                          │
            └──► إعادة للتعديل / رفض ◄─────────────────────────┘           إلغاء قبل التنفيذ
```

- كل صرف مربوط **ببند ميزانية** في المشروع.
- لا يُعتمد صرف من تحصيل **قيد التحقق** أو من تعهد غير محصّل: الرصيد المتاح = المحصَّل المؤكد − المحجوز − المنفَّذ.
- المعتمد لازم يكون حده في مصفوفة الاعتماد (الصرف) ≥ مبلغ الطلب، وما يكونش هو منشئ الطلب.
- مناقلات الميزانية بين البنود لها طلب واعتماد منفصل.

## 3) التحصيل

```
اختيار المشاريع (مساحة التحصيل) ─► المتبرع ─► طريقة الدفع ─► المراجعة ─► تأكيد
   نقدي / نقاط بيع مقبولة / إلكتروني ناجح  ─► مؤكد + سند فوري
   تحويل بنكي / إلكتروني معلق            ─► قيد التحقق ─► (قبول ⇒ سند) أو (رفض ⇒ فشل)
```

- التبرع يُوزَّع على **مشاريع** فقط (مش على برنامج)، والسند الواحد يغطي كل البنود.
- كل تأكيد له **مفتاح عدم تكرار** (Idempotency): الضغط مرتين أو انقطاع الشبكة لا ينتج سندين.
- أول طباعة للسند يعملها المحصّل نفسه؛ إعادة الطباعة تحتاج صلاحية وتتسجل.
- **التعهد** نية فقط: لا يُحتسب تحصيلًا ولا يصدر له سند.
- **الاتفاقية**: مسودة ─► مراجعة ─► بانتظار التوقيع ─► سارية ─► مكتملة (أو ملغاة/معدّلة). مجموع الدفعات = إجمالي الاتفاقية.
- **العيني**: يُسجل بالكمية والحالة، والقيمة التقديرية تُعتمد منفصلة ولا تدخل في السند النقدي.
- **العهدة**: المحصّل يسلّم النقدي للخزينة/البنك؛ ده نقل لنفس المال مش تحصيل جديد. **المطابقة** تقارن الحركات بكشوف البنك والرسوم.

## 4) الاسترداد وإعادة التخصيص والتصحيح

| الطلب | المسار | ملاحظات |
|---|---|---|
| استرداد | طلب ─► اعتماد (ضمن الحد، ومش صاحب الطلب) ─► تنفيذ بمرجع | يخفّض التحصيل المؤكد للمشروع ويُرسل للمشاريع الداخلية |
| إعادة تخصيص | طلب بموافقة المتبرع ─► اعتماد ─► نقل | يخفّض الأصل ويزوّد المشروع الجديد مع فحص سقفه |
| تصحيح سند | طلب ─► اعتماد | السند لا يُحذف ولا تُعدّل قيمته؛ الإلغاء يعكس الأثر والتصحيح يصدر سندًا بديلًا مرتبطًا |

## 5) الربط بين النظامين

- كل حدث (إتاحة مشروع، إيقاف، تحصيل مؤكد، استرداد، إعادة تخصيص) يُكتب في **Outbox** داخل نفس الـ Transaction بتاع العملية.
- خدمة خلفية ترسل الرسائل وتعيد المحاولة تلقائيًا؛ الطرف المستقبل يمنع التكرار بـ **Inbox** بمفتاح فريد.
- شاشة **الإدارة › متابعة الربط** تعرض الرسائل المعلقة والفاشلة، و"إعادة الإرسال" آمنة.

## 6) الإدارة

| الشاشة | الوظيفة |
|---|---|
| المستخدمون | إنشاء/تعديل/تعطيل، المركز، الأدوار، كلمة مرور، فك القفل (5 محاولات خاطئة ⇒ قفل 15 دقيقة) |
| الأدوار والصلاحيات | مصفوفة كاملة لكل دور، تعديل جماعي بسبب موثّق، نسخ دور قائم |
| المراكز | المراكز والإدارات؛ المستخدم يرى مركزه فقط إلا مع صلاحية "نطاق كل المراكز" |
| مصفوفة الاعتماد | الحد الأعلى لكل دور في كل نوع عملية (اختياريًا لكل مركز/نوع مصروف) |
| التفويضات | تفويض مؤقت لصلاحية الاعتماد بفترة وسبب |
| إعدادات النظام | أيام تنبيه انتهاء الترخيص، نسب تنبيه السقف، مدة حجز المعلق، بادئة السندات، المبالغ السريعة… |
| سجل الإجراءات | بحث بالمستخدم/الإجراء/المرجع/الوحدة/التاريخ مع عرض القيم قبل وبعد |
| متابعة الربط | حالة رسائل الربط وإعادة الإرسال |
